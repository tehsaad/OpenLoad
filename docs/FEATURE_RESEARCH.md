# Feature Research (Clean-Room)

This document lists the user-visible features of Internet Download Manager (IDM) that inspired OpenLoad, and how OpenLoad implements each one independently.

**Method and boundaries**

* Sources were limited to IDM's **publicly available product descriptions** (its official website's feature list and help pages) and **ordinary user-visible behaviour** of download managers. The research covered *what* a feature does for the user, never *how* IDM implements it.
* No IDM binary was decompiled, disassembled or inspected, and no IDM code, text, icons, artwork or branding was copied. OpenLoad's name, icon, colours, layout and code are original.
* OpenLoad makes **no claim of compatibility** with IDM, its file formats, its browser extensions or its internal architecture.
* Where this document says "IDM", it means the publicly described feature. Statements about OpenLoad were verified with the automated tests listed in `docs/TESTING.md`.

| # | Feature | Publicly described behaviour | OpenLoad approach | Limitations | Acceptance criteria (test) |
|---|---|---|---|---|---|
| 1 | Add download from a URL | The user pastes a link, then chooses a folder and file name. | `AddDownloadDialog` validates the URL with `validateDownloadUrl` (http/https only, no credentials), then probes the server in the background. It fills in the size, resume support and suggested name, and the user can cancel the check. | No authentication or cookies are supported. | `tst_ui::addDialogInspectsServer`, `addDialogRejectsBadUrls`, `tst_core::urlValidation` |
| 2 | Suggested file name | The name comes from the server or the link. | `Content-Disposition` (`filename*` and `filename`), then the final URL after redirects. Every name passes through `sanitizeFileName` (no path separators, `..`, control characters or Windows device names). | Names longer than 200 characters are shortened. | `tst_core::sanitizeFileNames`, `contentDisposition`, `tst_network::probeSanitizesServerFileName` |
| 3 | Pause and resume | Interrupted downloads continue where they stopped, if the server allows it. | `Range: bytes=N-` plus `If-Range`, and an exact `Content-Range` check. A `200` reply means a restart from zero, never an append. The ETag, Last-Modified and size are revalidated before every resume. | Servers without range support restart from zero. The UI warns about this when the download is added. | `tst_network::resumeWithRanges`, `resumeWhenServerIgnoresRanges`, `resumeAfterResourceChanged`, `wrongContentRangeIsRejected`, `tst_manager::pauseAndResume` |
| 4 | Segmented (multi-connection) downloading | A file is split into parts downloaded over several connections. | `planSegments` creates non-overlapping ranges of at least 1 MiB (at most 16 segments, as set in Settings). Each segment goes to its own file and every response range is verified. The segments are assembled and verified before the rename. | OpenLoad uses a static split; IDM describes "dynamic" segmentation. Segmentation helps only when the server limits each connection (see the benchmark). | `tst_network::segmented*`, `tst_manager::segmentedPauseAndResume`, benchmark in `TESTING.md` |
| 5 | Fallback when ranges are unsupported | The download continues with one connection. | `SegmentedResult::rangeUnsupported` sends the worker to single-connection mode and adds a note for the user. | — | `tst_network::segmentedDetectsIgnoredRanges`, `workerFallsBackToSingleConnection` |
| 6 | Automatic retry and recovery | Broken downloads are resumed automatically. | `RetryPolicy` separates transient failures (timeouts, resets, 5xx, 429 with `Retry-After`) from permanent ones (4xx, TLS verification, disk full, permissions). It uses bounded exponential backoff, and the attempt count and delay are configurable. | Never retries forever. Permanent errors are never retried. | `tst_core::retryPolicy`, `tst_manager::transientErrorsAreRetried`, `retriesAreBounded`, `permanentErrorsAreNotRetried` |
| 7 | Recovery after a crash or restart | The download list survives restarts. | SQLite persistence and `applyStartupRecovery`. Interrupted tasks become *Paused · Interrupted*, and byte counts come from the files on disk. | Nothing resumes automatically after a crash; the user decides. | `tst_storage::recovery*`, `tst_manager::gracefulRestartRestoresTasks`, `crashRecovery` |
| 8 | Download queue | Downloads wait in a queue that the user starts and stops. | `DownloadQueue`: higher priority first, then FIFO, limited by "Simultaneous downloads". "Start now" bypasses a stopped queue. "Stop queue" sends the downloads the queue started back to the queue. | One queue; IDM describes several named queues. | `tst_queue::*`, `tst_manager::queueWaitsUntilStarted`, `stopQueueRequeuesQueueTasks`, `concurrencyLimitIsRespected` |
| 9 | Scheduler | Start or stop downloads at set times. | A daily start time and an optional stop time, including windows that cross midnight. The missed-start policy is documented and tested. Times are in local time. | Runs only while OpenLoad is open. No "shut down computer when done". | `tst_queue::scheduler*` |
| 10 | Speed limiter | Limit how much bandwidth downloads use. | A global KB/s cap, split evenly across running downloads by a token bucket (`RateLimiter`) and re-balanced whenever a download starts or stops. | Approximate over one-second windows. | `tst_network::bandwidthLimitIsApplied`, `tst_manager::bandwidthLimitFromSettings` |
| 11 | Connection count setting | The user chooses how many connections a download may use. | "Connections per download" (1–16) on the Settings and Queue pages, used when the next download starts. | A running download keeps its segment plan. | `tst_core::segmentPlanning` |
| 12 | Progress, speed, time left | Live progress, transfer rate and remaining time. | A smoothed speed (exponential moving average, `SpeedMeter`). The ETA is shown **only** when the size and speed are known; otherwise "—" or "Unknown". An unknown size shows an activity stripe, not a fake percentage. | — | `tst_core::progressAndEta`, `speedMeterSmooths` |
| 13 | Categories and history | Downloads are grouped by type, and history is kept. | A category based on the file extension (Video, Audio, Archive, Document, Program, Image, Other). History is kept in SQLite, with search and state filters on the Dashboard. | Categories do not yet have their own folders. | `tst_core::categories` |
| 14 | File integrity | Verify downloaded files. | Optional SHA-256 from a **trusted** source. The result is shown as *Verified*, *Mismatch* or *Not verified*. A hash computed locally alone is never presented as proof. | MD5 and SHA-1 are deliberately not offered. | `tst_network::workerVerifiesChecksum`, `workerReportsChecksumMismatch` |
| 15 | Error reporting | Clear messages when something fails. | Every error has plain-language text (for example "HTTP 404 Not Found: the file does not exist at this address"). It appears in notifications, tooltips and the Details page. | — | `tst_network::httpErrorsAreClassified` |
| 16 | Browser integration | A browser extension hands downloads to the manager. | **Not implemented** (stretch goal). The design and security requirements are in `docs/SECURITY.md`. The command line `openload --add <url>` is the current hand-off. | — | — |

Features that IDM describes and that OpenLoad deliberately leaves out:

* video or stream grabbing from web pages;
* the site grabber or spider;
* any DRM, login or paywall circumvention;
* torrents.
